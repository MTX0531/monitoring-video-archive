# 项目流程（rtsp-puller 监控录像归档）

## 一、整体流程

```
大华 NVR 录像机（RTSP 回放 + 可选 FTP 推送）
   │
   ├─────────────── RTSP 拉取路径 ───────────────┐
   │                                            │
   ▼                                            ▼
nvr_puller.py                             ftp_receiver.py（tools/）
   │ 按日定位游标（落后自动补漏 ≤7天）              │ 接收录像机 FTP 推送
   ▼                                            ▼
RTSP 回放拉流（并发 N 路提速）                 转封装 mp4 + 命名
   │                                            │
   ▼                                            ▼
段文件 ≤30min ──▶ 校验可播放（失败自动修复）──▶ 统一归档根目录
   │                                            （<门店名>_<通道>_<起>_<止>_device.mp4，按日组织）
   ▼
retention 清理：按天数 → 容量上限 → 磁盘剩余空间，三级永久删除
```

## 二、核心子流程

### 2.1 RTSP 拉取（nvr_puller.py）
1. **启动探测**：读录像机设备名（`General.MachineName`）与通道名（`ChannelTitle`），用于归档命名
2. **游标推进**：从 `start_time` 起按日归档；落后于目标日时自动逐日补漏（`catchup_max_days`，默认 7 天）
3. **拉流**：每段 ≤30 分钟，按 `parallel_streams` 并发回放提速（单路固定 1 倍速，整机 15 路上限）
4. **空档秒判**：RTSP `DESCRIBE` 返回 404 = 无录像，直接跳过
5. **校验修复**：`verify_playable` 探测能否解码，失败先无损重封装，再转码兜底
6. **命名归档**：`<门店名>_<通道名>_<起>_<止>_device.mp4`，`organize_by_date` 按日建目录
7. **钩子**：`hooks.on_segment_saved` 可接 AI 稽核/上传 Notion 等外部命令

### 2.2 FTP 接收（tools/ftp_receiver.py，可选）
1. 录像机 FTP 推送（push 模型，只推新文件）
2. 接收端磁盘闸门：剩余空间 < `min_free_gb` 直接拒收（防写满系统盘）
3. 入库：后台转封装成 mp4 + 按同一命名规则放入归档根目录，收件箱原件销毁
4. **自动收工**：连续空闲 `idle_exit_minutes` 分钟（无连接 + 无新文件 + 入库队列清空）自行退出，退出前自动关闭设备端 FTP 开关并留快照供回滚

### 2.3 留存清理（retention）
- 按**保留天数** → **归档总量上限** → **磁盘剩余空间下限**三级清理
- 最近 `protect_recent_hours` 小时内的录像受保护不删
- `delete_mode=permanent` 为永久删除（默认，防占空间）

## 三、状态与数据

| 数据 | 位置 | 说明 |
|---|---|---|
| 归档视频 | `archive.root_dir` | 按日组织，命名含门店/通道/时间 |
| 游标状态 | `state/state.json` | 断点续传，重启不重复拉 |
| 设备名称缓存 | `state/device.json` | 读不到设备时的命名兜底 |
| 索引 | `state/index.jsonl` | 已拉片段登记 |
| 日志 | `logs/` | 按天滚动，保留 `log_keep_days` |

## 四、多门店部署

每个门店/通道一个独立实例（各自 config、state_file、log_dir），注意：
- 各实例 `parallel_streams` 之和 ≤ 15（整机共享）
- 归档根目录按门店隔离，避免命名冲突
- 详细方案见 `docs/多门店部署方案.md`
