# 使用须知（门店监控录像本地归档 rtsp-puller）

本文件面向部署和运维人员。开始前请先阅读 `README.md` 了解系统全貌与实机验证结论。

---

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Windows / macOS / Linux（脚本提供 Windows bat 与开机自启方案） |
| Python | 3.10+（仅标准库 + 少量依赖） |
| ffmpeg | **必须**（拉流与转封装依赖）。Windows 可放 `bin/` 或加入 PATH |
| 录像机 | 大华 NVR（实测 DH-NVR4216-HDS2；支持 RTSP 回放即可） |
| 磁盘 | 归档目录所在盘剩余空间建议 ≥ 2× 日素材量（自动清理兜底） |

## 二、配置步骤

1. 复制配置模板：
   ```
   cp config.example.json config.json
   ```
2. 编辑 `config.json` 关键字段（**占位符必须替换为真实值**）：

| 字段 | 说明 |
|---|---|
| `nvr.host` | 录像机 IP（占位 `192.168.2.10` → 真实 IP） |
| `nvr.username` / `nvr.password` | 录像机 Web/RTSP 账号（密码占位 `<NVR_PASSWORD>`） |
| `archive.root_dir` | 归档根目录（`auto` = 自动选剩余空间最大的盘） |
| `archive.start_time` | 归档起始时间 |
| `ftp.user` / `ftp.password` | FTP 接收账号（密码占位 `<FTP_PASSWORD>`） |

## 三、运行方式

| 场景 | 命令 |
|---|---|
| 单次运行（当日归档，前台） | `python nvr_puller.py` |
| 每日任务 | `run_daily.bat` |
| 常驻运行 | `run_forever.bat` |
| 开机自启（Windows） | `powershell -ExecutionPolicy Bypass -File install_startup.ps1` |
| 卸载自启 | `uninstall_startup.ps1` |
| FTP 接收端 | `run_ftp.bat`（需防火墙放行 21 + 60000~60099 被动端口段） |
| 运行全部自测 | `python tools/run_all_tests.py` |

## 四、重要提醒

1. **营业时段限制**：默认仅 09:30~22:30 拉流（`schedule` 段），避免占用录像机回放通道；`mode=footage` 时空档直接跳过。
2. **并发上限**：整机共享回放通道，实测上限 **15 路**。多通道部署时各实例 `parallel_streams` 之和不要超过 15。
3. **RTSP 认证避坑**：Digest nonce 与 TCP 连接绑定——必须复用同一条连接重发认证，所以用 ffmpeg 拉流，脚本自带探测也按同连接实现。
4. **自动清理**：`retention` 段按 天数/容量/磁盘剩余 三级清理，`delete_mode=permanent` 为永久删除，不可恢复。
5. **脱敏占位符**：`config.example.json` 内地址密码均为占位，部署时必须替换，详见 `脱敏说明.md`。

## 五、常见问题（FAQ）

**Q：拉流一直 401 Unauthorized？**
A：nonce 绑定 TCP 连接（见重要提醒 3）；另确认并发启动时错开启动时间（`start_stagger_seconds`，实测同秒并发会导致部分 401）。

**Q：视频拉下来打不开/卡住？**
A：脚本带 `verify_playable` 校验，不合格自动修复（先无损重封装再转码兜底）。若仍有问题检查网络与录像机并发。

**Q：磁盘被写满？**
A：`retention` 的 `min_free_gb` 兜底会自动从最旧录像清理；FTP 接收端也有磁盘闸门（拒收）。

**Q：FTP 传不上来？**
A：确认 Windows 防火墙放行被动端口段 60000~60099；大华上传走 PASV，该段不通会"连接成功但传不了文件"。

**Q：`state/`、`logs/`、`ftp-inbox/` 是什么？**
A：运行状态、日志与 FTP 收件箱，均为运行时产物，**不提交 git**（仓库内已排除）。
